# サーバー設定と公開範囲

## 公開してよい設定

SupabaseのプロジェクトURL・publishable key・管理者のAuth UUIDは認証用の秘密ではありません。実際の権限はDBのRLS・関数の実行権限・Edge Functionで検証します。管理者のメールアドレスとパスワード、secret/service_role key、ログイン後のアクセストークンをGitへ追加しないでください。

非公開写真・下書き・公開処理履歴はSupabaseに保存されます。このリポジトリには保存内容のダンプを含めません。設定SQLとサーバーコードは公開可能ですが、秘密値は含めません。

## Supabaseの登録

`supabase/migrations/` の01から09を番号順に一度だけ実行します。既存環境ですでに実行済みのSQLは再実行しません。GitHubへのプッシュではDBは更新されません。このプロジェクトの管理者UUIDやプロジェクトURLを使用しているので、別環境へ移植する際は置き換えてください。

Edge Functionsに次を登録します。各フォルダのindex.tsがそのまま登録するソースです。JWT検証は有効にし、管理者ログインのアクセストークンで呼び出します。

- `publish-spot-photo`: 確認した非公開写真を公開用にコピーしてカードを更新
- `delete-private-photo`: 条件を満たす未使用の非公開写真を削除
- `cleanup-failed-photo`: 失敗確定から24時間以上経過した未使用の公開用コピーを整理

サーバーの秘密キーはSupabaseが注入する環境変数から読みます。実際のキーをソースへ貼り付けません。許可OriginはこのGitHub PagesのホストとHTTPのlocalhost / 127.0.0.1です。独自ドメインを導入したら関数の許可リストも更新します。

## 操作上の注意

- ローカル管理画面からの公開・削除も同じSupabaseへの本番操作です。
- 写真公開後の取り消しはカード情報を戻す操作です。画像のキャッシュや第三者の保存先までは消せません。
- 整理は自動処理ではありません。管理者が対象を確認して実行します。
- 新規の点・線・面は端末内編集とプレビューまでです。オンライン公開は未対応です。
- Supabaseが応答しない場合、利用者マップは元のJSONへ戻して表示します。

## テスト

Node.jsを使用します。単体テストは外部サービスへ書き込みません。

```sh
node --test tests/*.test.cjs
```

ブラウザテストにはPlaywrightを別途インストールします。`CHROME_PATH`で既存のChrome実行ファイルを指定するか、PlaywrightのChromiumをインストールしてください。各`tests/*-browser.cjs`をNode.jsで実行します。モックテストは本番へ保存・公開・削除を行いません。地図描画テストはベースマップへの通信を行います。

生成した画像は`test-artifacts/`へ保存し、Git対象から除外します。SupabaseのSQL・サーバー関数は別途ローカル互換環境とモックで検証しています。実環境の権限・通信・削除確認は、公開して問題のない不要なテスト写真だけで行ってください。
